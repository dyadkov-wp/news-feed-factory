# ADR-PROC-0005: Запрет ABSPATH-guard в классах src/

**Статус:** Proposed
**Создано:** 2026-10-09
**Обновлено:** 2026-10-09

## Контекст

Классы `NWFF\Install\Schema` и `NWFF\Cache\TransientCache` начинались с
классического WP-guard'а:

```php
if ( ! defined( 'ABSPATH' ) ) {
	exit;
}
```

Этот паттерн уместен в **главном файле плагина**
(`news-feed-factory.php`), который WordPress может запросить напрямую по
URL. В классах `src/`, подключаемых через PSR-4-автозагрузчик Composer,
он даёт опасный побочный эффект.

Под unit-бутстрапом (`tests/bootstrap-unit.php`) WordPress не
загружается, константа `ABSPATH` не определена. Первое же обращение
`class_exists( TransientCache::class )` в SmokeTest приводит к:

1. PSR-4-автозагрузка читает файл класса.
2. Top-level `if ( ! defined( 'ABSPATH' ) )` срабатывает.
3. `exit;` завершает процесс PHPUnit с кодом 0.

PHPUnit не успевает напечатать ни результат SmokeTest, ни summary. Файл
`.phpunit.result.cache` показывает «0 ошибок», `composer check`
показывает зелёный — **silent exit маскируется под успех**. Тест,
который должен ловить именно такие ситуации, сам стал жертвой
untested-пути.

Это не первый симптом — мы заметили отсутствие SmokeTest в выводе через
несколько итераций диагностики. До этого падение было невидимым.

## Решение

В классах `src/` (PSR-4-пространство `NWFF\`) **запрещены
top-level side-effects**. В частности, запрещён guard `ABSPATH` на
верхнем уровне файла.

Разрешено:

- `ABSPATH` **внутри методов** (`Schema::activate()` — `require_once
  ABSPATH . 'wp-admin/includes/upgrade.php'`).
- Guard `ABSPATH` в главном файле плагина `news-feed-factory.php`.
- Guard `ABSPATH` в любых файлах вне `src/`, если они подключаются
  WordPress напрямую (`templates/`, `admin/` — если появятся).

Защита от прямого HTTP-запроса к файлу класса — ответственность
веб-сервера (правило `deny from all` для `wp-content/plugins/*/src/`)
или стандартного WP-поведения. В нормально устроенном WP файлы `src/`
не запрашиваются по URL напрямую.

## Последствия

**Плюсы:**

- Unit-тесты грузят классы без WP и без неожиданных `exit`.
- PSR-4-контракт соблюдён: файл класса описывает класс, не выполняет
  логику.
- SmokeTest снова становится значимым — он ловит именно такие
  регрессии.

**Минусы:**

- Разработчик, привыкший ставить guard везде, может поставить его
  случайно. Митигация — этот ADR + правило линтера (см. ниже).
- Если кто-то настроит веб-сервер без `deny from all` для `src/`,
  возможен прямой доступ к файлам классов. Это вернёт fatal `class not
  found` вместо тихого `exit` — не хуже, чем сейчас.

## Точки расширения / автоматизация

PHPCS-правило `WordPress.Security.ABSPATH` **не ловит** этот случай —
оно требует, чтобы guard был, а не чтобы его не было. Возможные
варианты автоматизации (отложены):

- Снифф-плагин для PHPCS на основе `Squiz.PHP.DiscouragedFunctions`
  или кастомный.
- PHPStan-расширение, запрещающее `exit`/`die` на top-level.

Пока — правило фиксируется ADR и ревью.

## Альтернативы

- **Оставить guard, добавить `ABSPATH` в `tests/bootstrap-unit.php`.**
  Отклонено: подмена реальности. Тест-инфра начинается врать о том,
  в каком окружении работают классы. Завтра появится класс, который
  требует `WPINC`, потом `wpdb`, и bootstrap станет симулякром WP
  вместо unit-бутстрапа.
- **Ловить `exit` в bootstrap через `register_shutdown_function`.**
  Отклонено: хрупко, маскирует причину. Полезно как **дополнительная**
  защита в тест-инфре (см. BACKLOG), но не как решение.
- **Оставить как есть, писать только integration-тесты.**
  Отклонено: противоречит ADR-PROC-0004 (unit без WP) и убивает
  смысл SmokeTest.

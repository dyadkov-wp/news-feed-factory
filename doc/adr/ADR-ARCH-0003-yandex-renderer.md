# ADR-ARCH-0003: Рендерер Яндекса

**Статус:** Proposed
**Создано:** 2026-10-02
**Обновлено:** 2026-10-02

## Контекст

Яндекс — первый рендер (ADR-PRODUCT-0001). Формат — «Свежее и
актуальное»: RSS 2.0 с namespace `yandex` и `media`. Требования
стабильны и хорошо документированы.

Рендер строится поверх нормализации (ADR-ARCH-0002) и ядра
(ADR-ARCH-0001). Специфика Яндекса: набор жанров, одна рубрика
на материал, полный текст в `yandex:full-text`.

## Решение

### Структура файлов

```
src/
├── Render/
│   ├── YandexRenderer.php
│   └── Yandex/
│       └── GenreResolver.php
```

`YandexRenderer` реализует `RendererInterface` (ADR-ARCH-0001,
ADR-ARCH-0002). `GenreResolver` — отдельный класс, потому что
логика вычисления жанра нетривиальна и тестируется отдельно.

### Метаданные рендера

```php
public function get_slug(): string {
    return 'yandex';
}

public function get_content_type(): string {
    return 'application/rss+xml; charset=UTF-8';
}
```

### Конфигурация нормализации

```php
public function get_normalization_config(): array {
    return [
        'max_content_length' => null,
        'truncate_mode'      => 'none',
        'truncate_limit'     => 0,
        'allowed_html'       => null, // базовый wp_kses
        'image_min_width'    => null,
        'image_min_height'   => null,
        'include_terms'      => true,
    ];
}
```

`include_terms = true` — нужен для рубрики и для GenreResolver
(он смотрит теги).

`truncate_mode = 'none'` — Яндекс принимает до 10 МБ, а у нас
глубина 4–12 часов. Обрезать `yandex:full-text` не нужно.
Ресурсный лимит тоже не ставим: при малой глубине объём
контролируем.

### Логика жанра

`GenreResolver::resolve( array $item, array $settings ): string`

Порядок проверки:

1. Тег с ID `tag_interview` (из настроек) → `interview`.
2. Тег с ID `tag_article` (из настроек) → `article`.
3. Тег с ID `tag_lenta` (из настроек) → `lenta`.
4. Переключатель `by_length` включён и длина `content` < 80 → `lenta`.
5. Иначе → `message`.

Приоритет: интервью > статья > лента > длина > дефолт.

Правило из ADR-PRODUCT-0001: ID тегов **не хардкодятся**,
читаются из `nwff_settings`.

Если ID не задан (`0` или пусто) — соответствующая проверка
пропускается.

### Настройки рендера

Регистрируются через фильтр `nwff_settings_fields` (ADR-ARCH-0001).
Контейнер — `nwff_settings['yandex']`.

| Ключ | Тип | Дефолт | Назначение |
| --- | --- | --- | --- |
| `enabled` | checkbox | off | Включить ленту |
| `tag_interview` | number | 0 | ID тега «Интервью» |
| `tag_article` | number | 0 | ID тега «Статья» |
| `tag_lenta` | number | 0 | ID тега «Лента» |
| `by_length` | checkbox | on | Определять lenta по длине |

`feed_slug` — общий (ядро). URL формируется как
`/{feed_slug}/yandex.xml`.

### Эндпоинт

Регистрируется через фильтр `nwff_feed_endpoints`:
`/feed/yandex.xml`. Если `enabled = false` — 404.

### Структура XML

```xml
<?xml version="1.0" encoding="UTF-8"?>
<rss version="2.0"
     xmlns:yandex="http://news.yandex.ru"
     xmlns:media="http://search.yahoo.com/mrss/">
  <channel>
    <title>Название сайта</title>
    <link>https://example.com/</link>
    <description>Описание сайта</description>
    <language>ru</language>
    <item>
      <title>Заголовок</title>
      <link>https://example.com/post/123</link>
      <pubDate>Mon, 02 Oct 2026 12:00:00 +0300</pubDate>
      <author>Иван Иванов</author>
      <category>Политика</category>
      <description>Аннотация</description>
      <yandex:genre>article</yandex:genre>
      <yandex:full-text><![CDATA[полный HTML]]></yandex:full-text>
    </item>
  </channel>
</rss>
```

Поля, которых нет (например, `description` при пустом
`excerpt`), — не выводятся целиком.

### Правила вывода полей

| Элемент | Источник | Обязателен | Условие вывода |
| --- | --- | --- | --- |
| `title` | нормализованный `title` | да | всегда |
| `link` | нормализованный `link` | да | всегда |
| `pubDate` | нормализованный `published` | да | всегда |
| `yandex:full-text` | нормализованный `content` | да | всегда (в CDATA) |
| `author` | `get_the_author_meta('display_name')` | нет | если автор есть |
| `category` | первая рубрика из `terms` | нет | если рубрика есть |
| `description` | нормализованный `excerpt` | нет | если `excerpt` не пуст |
| `yandex:genre` | `GenreResolver` | нет | всегда (даже `message`) |

**Одна рубрика.** Яндекс принимает одну `category` на item.
Берём **первую категорию** из `terms` (в порядке, как вернул
`wp_get_post_terms`). Если категорий нет — элемент не выводится.

Приоритет рубрик (какая «главная») — не вводим. Если редакторы
попросят — отдельным решением.

**`title` — до 200 символов.** Требование Яндекса. Обрезаем
форматно через `Truncator`, если длиннее. `mb_substr` по границе
слова.

**Дата — RFC 2822** с часовым поясом сайта:
`DateTimeImmutable` из нормализации → `->format('D, d M Y H:i:s O')`.

### Генерация XML

**Вручную, через `sprintf` и heredoc.** Без `DOMDocument` и
`SimpleXML`.

Причины:

- Namespace `yandex` и `media` — проще в шаблонной строке.
- `yandex:full-text` требует CDATA — `DOMDocument` работает с
  ним неудобно.
- Экранирование: для текстовых полей — `esc_html`, для URL —
  `esc_url`, для CDATA — проверка на `]]>` (замена на `]]]]><![CDATA[>`).
- Контроль над форматом — точно как в требовании Яндекса.

Отдельный класс `RssWriter` не вводим — он появится, когда
будет второй RSS-рендер (Google). Пока Yandex самодостаточен
(YAGNI).

### Обработка ошибок

- Пустой набор items → отдаём валидный RSS с пустым `<channel>`
  (без `<item>`). Это не ошибка.
- Нет `title` в нормализованном элементе → пропускаем item,
  `WARNING`.
- Нет `link` → пропускаем item, `WARNING`.
- Нет `published` → пропускаем item, `WARNING` (Яндекс требует
  `pubDate`).
- `content` пуст → всё равно выводим `<yandex:full-text>` с
  пустым CDATA (Яндекс может отклонить, но это ответственность
  редактора, не плагина).

Плагин не «исправляет» контент: не убирает точку в конце
заголовка, не ругается на CAPS, не добавляет автора. Это
рекомендации Яндекса к редакции, а не требования формата.

### Кэширование

Общее, через `TransientCache` (ADR-ARCH-0001). Ключ включает
`feed_type = 'yandex'`. TTL — из `depth_hours` общих настроек.

### Тестирование

- **Unit:** `GenreResolver` — все ветки приоритета, включая
  пустые теги, отключённый `by_length`, границу длины 80.
- **Unit:** `YandexRenderer::render()` — фикстуры
  нормализованных элементов, проверка XML через
  `simplexml_load_string` и XPath.
- **Integration:** полный путь Collector → Normalizer →
  Renderer на реальных записях (wp-env). Помечается
  `@group integration`.

Тесты XML: проверяем структуру, обязательные элементы,
корректность namespace, CDATA.

## Последствия

**Плюсы:**

- Рендер тонкий: только XML и специфика жанра.
- `GenreResolver` тестируется отдельно.
- Никаких XML-библиотек — полный контроль над форматом.
- Настройки — через общий Settings API, не плодят своих
  страниц.

**Минусы:**

- Ручная генерация XML — надо аккуратно с экранированием.
  Митигается тестами через `simplexml_load_string`.
- `category` — первая из `terms`. Если редактор ожидает
  «главную», будет несоответствие. Осознанный компромисс MVP.
- `RssWriter` не выделен — когда появится Google, часть кода
  придётся вынести. Принято по YAGNI.

**Риски:**

- Сайт без категорий → ни одного `<category>`. Яндекс не
  требует, но может использовать для рубрикации. Приемлемо.
- Тема сайта переопределяет `the_author` — берём
  `get_the_author_meta`, не шаблонный вывод. Устойчиво.
- `title` ровно 200+ символов → обрезка. Если это ломает смысл
  — ответственность редактора.
- CDATA и `]]>` в тексте — редкий случай, но обрабатываем.

## Альтернативы

- **`DOMDocument` для генерации.** Отклонено: namespace и
  CDATA неудобны, код громоздче.
- **`SimpleXML`.** Отклонено по тем же причинам.
- **Библиотека типа `sabre/xml`.** Отклонено: внешняя
  зависимость ради одной задачи; для репозитория WP —
  дополнительный вес.
- **Вынести `RssWriter` сразу.** Отклонено: YAGNI. Второй
  рендер покажет, что общего.
- **Логика жанра в ядре.** Отклонено (ADR-ARCH-0002): жанр —
  специфика Яндекса.
- **`genre_override` на уровне записи.** Отклонено на этапе 1:
  достаточно тегов. Если попросят — отдельным решением.
- **`truncate_mode = 'first_paragraph'` для full-text.**
  Отклонено: Яндекс хочет полный текст.
- **Ресурсный `max_content_length`.** Отклонено: при глубине
  4–12 часов и лимите 10 МБ на фид объём не проблема. Введём,
  если увидим проблему.
- **Медиа (`media:group`).** Отложено. Яндекс не требует.
  Добавим после Google и Дзена — там медиа важнее.

## Открытые вопросы

- **Приоритет рубрик.** Сейчас — первая из `terms`. Если
  редакторы захотят «главную рубрику» — введём настройку
  или метаполе. Ждём обратной связи.
- **Медиа (`media:group`).** Когда добавлять? После Дзена,
  потому что там это обязательно. Порядок: Google → Дзен →
  медиа для всех.
- **`pdalink` (мобильная версия).** Отложено. Если сайт не
  имеет отдельной мобильной версии — не нужно. Яндекс не
  требует.
- **`yandex:theme_tags`.** Отложено. Нужен JSON-файл тем — за
  рамками плагина. Введём, если появится реальная потребность.

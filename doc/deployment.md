# Deployment

Deployment notes for production WordPress sites. Covers the web
server, HTTP caching and the Yandex feed URL.

## Feed URL

The Yandex feed is served at `/{feed_slug}/yandex.xml`. `feed_slug`
is configured under Settings → News Feed Factory → Core settings,
default `feed`. On the reference site the URL is
`https://oblgazeta.ru/feed/yandex.xml`.

Permalinks must not be "Plain": the feed endpoint relies on
`WP_Rewrite`. Any other permalink structure works.

## HTTP caching

The plugin caches the rendered XML in a transient for 5 minutes
(`cache_ttl`) and sends `Cache-Control: public, max-age=300,
s-maxage=300` on every response. If the web server or a CDN
overrides the header with a longer TTL, new posts will not appear
in the feed for Yandex's crawler until the override expires.

### Verify

```bash
curl -sI https://example.com/feed/yandex.xml | grep -i cache-control
```

Expected: `cache-control: public, max-age=300, s-maxage=300`.

If you see a different `max-age`, the header is being overridden.
Check:

```bash
# nginx / Angie
angie -T 2>/dev/null | grep -B2 -A2 'expires\|max-age'
# or
grep -rE 'expires|max-age|Cache-Control' /etc/angie/

# Active WordPress plugins (cache plugins may set the header)
wp plugin list --status=active
```

## Reverse proxies

If the site sits behind one or more reverse proxies (CDN, Varnish,
upstream nginx), any of them can override the plugin's
`Cache-Control` header. Diagnose with:

```bash
curl -sI https://example.com/feed/yandex.xml | grep -iE 'via|x-cache|age|cache-control|server|x-'
```

Look for `via`, `x-cache`, `age`, `cf-cache-status`. These identify
the layers. To find where `max-age` is set:

- Owned proxies: `nginx -T | grep -B2 -A2 'expires\|Cache-Control'`
  on each layer.
- CDN: check the panel for cache rules on `/feed/*.xml`.

Override on the proxy closest to the client:

```nginx
location ~ ^/feed/[^/]+\.xml$ {
    proxy_pass <upstream>;
    proxy_hide_header Cache-Control;
    add_header Cache-Control "public, max-age=300, s-maxage=300" always;
}
```

Without an override, Yandex will see new posts up to `max-age`
seconds after publication. This is not a plugin bug: the plugin
sends the correct header, but shared caches in front of the site
have the last word.

### Override in Angie / nginx

When the server sets `expires` for all responses, add a location
block that bypasses `try_files` so PHP's `Cache-Control` reaches
the client unchanged:

```nginx
location ~ ^/feed/[^/]+\.xml$ {
    include fastcgi_params;
    fastcgi_pass unix:/var/run/php8.4-fpm/php8.4-fpm.sock;
    fastcgi_param SCRIPT_FILENAME $document_root/index.php;
    fastcgi_param REQUEST_URI $request_uri;
    fastcgi_param PATH_INFO "";
    # No expires → PHP's Cache-Control passes through.
}
```

Adjust the `fastcgi_pass` socket to match the site's PHP-FPM setup.

### Override in Apache

```apache
<LocationMatch "^/feed/[^/]+\.xml$">
    Header set Cache-Control "public, max-age=300, s-maxage=300"
    Header unset Expires
</LocationMatch>
```

## Cache plugins

If the site runs WP Super Cache, W3 Total Cache, WP Rocket or
LiteSpeed Cache, exclude the feed URL from their page cache:

```
/feed/*.xml
```

The feed is already generated by our own transient cache; a
second layer only adds staleness.

## Verification after deployment

1. `curl -sI https://example.com/feed/yandex.xml | head -3` —
   HTTP 200, `Content-Type: application/rss+xml; charset=UTF-8`,
   `Cache-Control: max-age=300`.
2. `curl -s https://example.com/feed/yandex.xml | xmllint --noout -`
   — valid XML.
3. Create a test post and reload the feed — it must appear
   immediately (cache invalidated on `save_post_post`).
4. Uncheck "Include in feeds" on a post and reload — it must
   disappear immediately.
5. Run the Yandex feed validator:
   https://webmaster.yandex.ru/tools/feed-validator/

## Yandex.Webmaster

After the feed passes validation:

1. Yandex.Webmaster → Publisher Center → "Свежее и актуальное".
2. Add the feed URL.
3. Wait for validation (hours to days).

Yandex expects the feed to update within minutes of a new post.
A long `Cache-Control` or a cache plugin in front of the feed
will delay indexing; keep the effective TTL under 10 minutes.
